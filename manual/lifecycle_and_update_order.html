Lifecycle and update order

This page explains when the plugin's components do their work during a frame, what happens when they are enabled or disabled, and which values your own code can read at each point.

Order within a frame

UI Scalers are not updated in Update() or LateUpdate(). SmartUIManager runs one pass just before the canvases are rendered. Unity's built-in Canvas Scaler uses this same point in the frame.

  1. Update() and LateUpdate() of all scripts.
  2. The scaler pass:
    1. The screen safe area is read.
    2. Every enabled UI Scaler and UI Scaler behaviour that needs it is resized. When a UI Scaler is resized, its own Rect Transform is updated first. Next, a Smart UI Aspect Switch on it switches layouts and invokes its events, and then the resized listeners added from code run. The Smart UI Expanders, Smart UI Size Limiters and Smart UI Aspect Fitters under it are resized last.
    3. The Smart UI Mesh Fitter and the Smart UI World Follower place their objects and cameras, after all UI Scalers have their final size.
    4. AfterScalersUpdatedEvent is invoked.
  3. Unity rebuilds the canvas layout: Layout Groups, Content Size Fitters and graphics.
  4. The frame is rendered.

Every step after LateUpdate() happens in the same frame, so the result is on screen in the frame where the screen changed.

What your code can rely on

Where your code runs What it sees
Awake(), OnEnable(), Start() of the first frame Nothing is fitted yet. UI Scalers still have the size they were saved with.
Update(), LateUpdate() The sizes of the previous frame. A change of the screen in this frame is not applied yet.
A resized listener of a UI Scaler The final Rect Transform of that UI Scaler, and the layouts of its Aspect Switch. The behaviours under it, and other UI Scalers, may not be updated yet.
A listener of the Smart UI Aspect Switch The layouts are already switched.
SmartUIManager.AfterScalersUpdatedEvent All UI Scalers and their behaviours are final, and the Mesh Fitters and World Followers have placed their objects and cameras. Rect Transforms placed by Layout Groups or Content Size Fitters are rebuilt after this event, so they may still have the values of the previous frame.

To read fitted sizes before the first frame is rendered, for example in Start(), call Canvas.ForceUpdateCanvases() first. It runs the scaler pass and the canvas layout rebuild immediately. Call it once and only where needed, as it updates every canvas.

See Staying in sync with UI Scalers for AfterScalersUpdatedEvent, the resized listener and ScreenArea.

Component lifetime

  • Awake: a UI Scaler finds its parent and child UI Scaler behaviours. Nothing is resized.
  • OnEnable: a UI Scaler starts taking part in the scaler pass and takes control of its Rect Transform.
  • First scaler pass: a newly enabled UI Scaler is fitted in the first scaler pass after it was enabled, in the same frame. It is never fitted in Awake() or Start().
  • OnDisable: the UI Scaler leaves the scaler pass and releases its Rect Transform, which keeps its last fitted values. Nothing else moves.
  • Enabled again: the UI Scaler is fitted in the next scaler pass if its options, its group's options or the screen changed while it was disabled.

The Smart UI Expander, Smart UI Size Limiter and Smart UI Aspect Fitter follow the same rules. The Smart UI Mesh Fitter and the Smart UI World Follower start working in the first scaler pass after they are enabled, before AfterScalersUpdatedEvent is invoked. When disabled, the World Follower restores the projection and viewport of its camera. Smart UI Framing Bounds do not update anything themselves. They are read by the World Follower or Mesh Fitter they belong to, in that component's next update.

What triggers a resize

A UI Scaler is resized in the scaler pass only when something changed, otherwise the pass only checks that nothing changed. These changes cause a resize:

  • the screen resolution or the camera viewport of the Canvas;
  • the screen safe area, also when only the safe area changes, for example when a phone is turned upside down;
  • its options in the Inspector, or the options of its UI Scaler group, also when they are changed at runtime;
  • its Transform or its parent, for example when it is moved to another parent;
  • in the editor, the settings of the Smart UI Scaler window.

To make a UI Scaler refit in the next scaler pass for any other reason, set transform.hasChanged = true on it.

Layouts of the Smart UI Aspect Switch in the first frame

The Smart UI Aspect Switch switches layouts inside the first scaler pass, before the first frame is rendered. The correct layout is visible from the first frame.

A layout that was saved active is still active until that pass. Its scripts receive Awake(), OnEnable(), Start() and one Update() and LateUpdate() before it is deactivated, even when another variant wins on this screen. The layout that is activated by the switch receives Awake() and OnEnable() during the scaler pass and Start() and its first Update() in the next frame.

When the scripts in your layouts must only run in the layout that is used, deactivate all layouts before saving the scene. The Aspect Switch then only activates the layout that is used. In the "Fitted Reference Resolution" and "Reference Resolution" scaling modes, the UI Scaler then looks empty until a layout is shown with an "Edit Layout" button.

Edit Mode

All components run in Edit Mode too, so the layout looks the same as in Play Mode. The scaler pass runs whenever the editor redraws the canvases, for example when the Game view is resized or a value is changed in the Inspector. The "Scaling Mode" of the Smart UI Scaler window decides the size of UI Scalers in Edit Mode, and the Smart UI Aspect Switch only switches layouts in the "Preview" scaling mode.

In Play Mode the World Follower smooths its framing changes with unscaled time, so they also play while Time.timeScale is 0, for example in a pause menu.
